# Docker Setup Guide

## Prerequisites
- Docker installed
- Docker Compose installed
- `.env` file with the following variables:
  ```
  ISSUER_BASE_URL=<your-auth0-issuer-url>
  AUDIENCE=<your-auth0-audience>
  NAME_SPACE=<your-auth0-namespace>
  ```

## Running the Application

### Start the services
```bash
docker-compose up -d
```

This will:
- Start MongoDB on port 27017 with default credentials (admin/password)
- Build and start the GraphQL app on port 8081
- Set up a bridge network for service communication

### View logs
```bash
# All services
docker-compose logs -f

# Specific service
docker-compose logs -f app
docker-compose logs -f mongo
```

### Stop the services
```bash
docker-compose down
```

### Stop and remove volumes
```bash
docker-compose down -v
```

## Building the Docker image

### Build the image locally
```bash
docker build -t graphql-backend:latest .
```

### Run the image standalone
```bash
docker run -p 8081:8081 \
  -e MONGO_URI=mongodb://localhost:27017/graphql_db \
  -e ISSUER_BASE_URL=<your-issuer-url> \
  -e AUDIENCE=<your-audience> \
  -e NAME_SPACE=<your-namespace> \
  graphql-backend:latest
```

## Architecture

- **Multi-stage build**: Reduces final image size by separating build and runtime stages
- **Alpine Linux**: Lightweight base image (22MB vs 300MB+ with full Node)
- **dumb-init**: Ensures proper signal handling (SIGTERM) for graceful shutdown
- **Health checks**: MongoDB has a health check to ensure it's ready before the app starts
- **Volume mounts**: Source code is mounted for development hot-reload
- **Bridge network**: Services communicate via service name resolution

## Environment Variables

The app requires these environment variables (set in docker-compose.yml or .env):
- `PORT`: Application port (default: 8081)
- `MONGO_URI`: MongoDB connection string
- `ISSUER_BASE_URL`: Auth0 issuer URL
- `AUDIENCE`: Auth0 audience
- `NAME_SPACE`: Auth0 namespace
